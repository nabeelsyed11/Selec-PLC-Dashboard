2. Files to Deploy on the Raspberry Pi 5

Production Optimization: Because the React frontend is pre-compiled into frontend/dist/, you do NOT need Node.js or npm on the Raspberry Pi 5! The Python FastAPI backend serves both the API/WebSocket and the static UI assets directly on port 8000.

Copy the following clean directory structure to /opt/selec-iot-dashboard on the Raspberry Pi 5:

/opt/selec-iot-dashboard/ ├── backend/ # Python FastAPI backend source │ ├── app/ # Core, PLC poller, vibration, latency, control │ └── requirements.txt # Python dependencies (PyModbus, FastAPI, etc.) ├── config/ │ └── register_map.yaml # Selec MiBRX-6M register map & writable allowlist ├── frontend/ │ └── dist/ # Pre-built React production dashboard assets ├── tools/ │ ├── modbus_test.py # Diagnostic tool to verify PLC communication │ └── latency_benchmark.py # Latency profiler with CSV export ├── deploy/ │ └── systemd/ │ └── selec-iot.service # systemd service unit for auto-start on boot ├── .env # Active environment configuration └── .env.example

Files excluded from Raspberry Pi 5: frontend/node_modules/, frontend/src/, frontend/package.json, .git/, and host virtual environments (create fresh venv on the Pi).

3. Step-by-Step Deployment Commands on Raspberry Pi 5

Step 1: Install Base Packages
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-pip python3-venv git curl i2c-tools ufw
Step 2: Create Dedicated Service User
sudo useradd -r -s /bin/false -d /opt/selec-iot-dashboard -m iotgateway
sudo usermod -aG i2c,spi,dialout iotgateway

sudo mkdir -p /opt/selec-iot-dashboard
sudo chown -R $USER:$USER /opt/selec-iot-dashboard
Step 3: Copy Project Files & Install Python Virtualenv

After copying files into /opt/selec-iot-dashboard, initialize the Python runtime:

cd /opt/selec-iot-dashboard
python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r backend/requirements.txt
Step 4: Configure Production Parameters (.env)
cp .env.example .env
nano .env

Set the parameters for your physical PLC connection:

PLC_HOST=192.168.1.50                   # Set to physical Selec MiBRX-6M PLC IP
PLC_PORT=502                           # Modbus TCP Port 502
PLC_UNIT_ID=1                          # Modbus Slave ID (from Selec ladder)
SIMULATION_MODE=false                  # Disable simulation, read physical registers
ALLOW_REMOTE_CONTROL=false             # Safety default: keep false until ready to test writes
VIBRATION_SENSOR_INTERFACE=I2C_ADXL345 # Or MOCK
Step 5: Verify PLC Communication (Safe Read-Only)

Run the safe discovery tool before starting background services:

./venv/bin/python tools/modbus_test.py --host 192.168.1.50 --port 502 --unit 1
Step 6: Install and Enable systemd Service
sudo chown -R iotgateway:iotgateway /opt/selec-iot-dashboard
sudo cp deploy/systemd/selec-iot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now selec-iot
Step 7: Verify Service Health & Live Logs
sudo systemctl status selec-iot
sudo journalctl -u selec-iot -f

4. Accessing the Real-Time Web Dashboard

Open any web browser on your authorized engineering network:

http://<RASPBERRY_PI_IP>:8000     (Example: http://192.168.1.100:8000)

The dashboard connects via WebSockets (10 Hz) and provides 8 dedicated operational views:

1. Overview: Machine status indicator (RUNNING, IDLE, FAULTED, COMM_LOST), primary KPIs, PLC connection health, and Raspberry Pi 5 CPU/RAM/Temp.
2. Live Monitoring: Per-signal cards with live values, units, RTT timings, and quality badges (VALID, STALE, DISCONNECTED, SIMULATED).
3. Latency Analytics: Decomposition breakdown (Modbus RTT, Ingestion, Publish, Client Render) with P50, P95, P99 statistics and live CSV benchmark exporter.
4. Vibration Analysis: Time-domain oscilloscope waveform scope, RMS, Peak, Pk-Pk, Crest Factor, and 512-pt FFT spectral frequency bar chart.
5. Production: Total count, shift progress, throughput rate (parts/min), and Load Cell Zero Tare calibration action.
6. Energy Monitor: 3-Phase Voltage, Current, Active Power (kW), Power Factor, Grid Frequency, and Specific Energy per unit (kWh/product).
7. Alarms & Events: Active alarm banner, severity levels (INFO, WARNING, CRITICAL), and operator acknowledgement logging.
8. Safe Control Panel: Hardware interlock permissive status, allowlisted commands (Pusher, VFD), confirmation dialog, and immutable audit log.
